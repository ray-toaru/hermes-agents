# v2.6 Sandbox Recovery Simulation

## Status

Implemented as sandbox-only, read-only evidence. This slice does not enable real apply, release locks, execute rollback, mutate source profiles, read secrets, mutate runtime state, or orchestrate business work.

## Commands

```bash
scripts/simulate-sandbox-recovery <sandbox-audit.yaml> \
  --integrated-run <integrated-sandbox-run.yaml>

scripts/check-sandbox-recovery-simulation <simulation.yaml> \
  --audit-record <sandbox-audit.yaml> \
  --integrated-run <integrated-sandbox-run.yaml>
```

The simulator consumes v2.5 sandbox mutation audit evidence. It can infer a scenario from the audited status and failure stage, or record an explicit hypothetical scenario with `--scenario`. Hypothetical scenarios remain evidence-only and cannot authorize any action.

## Evidence Semantics

A recovery simulation records:

- the sandbox audit record hash;
- the integrated sandbox run hash;
- observed lock, rollback point, and post-apply validation evidence presence, including failed same-sandbox validation evidence;
- whether recovery is required;
- whether rollback would be a candidate in principle;
- that rollback was not executed;
- that lock release is not allowed or performed;
- that retry without manual review is not allowed.

Unknown states always fail closed. Stale or recovery-required lock scenarios preserve the lock-equivalent state for manual review.

## Non-Goals

This slice does not:

- create production recovery records;
- release real or sandbox locks;
- execute rollback;
- validate post-rollback state;
- write source repository evidence files;
- implement a real mutation command.

## Attack Review

### Attack: Treat recovery simulation as rollback execution

Rejected. The schema requires `rollback_executed: false`. The checker rejects records that claim rollback execution.

### Attack: Treat a successful recovery simulation as permission to release locks

Rejected. The schema requires `lock_release_allowed: false` and `lock_release_performed: false` for every scenario, including `no_recovery_required`.

### Attack: Use a hypothetical scenario to bypass audit evidence

Rejected. Hypothetical scenarios are explicitly marked with `hypothetical: true`; they still bind to the sandbox audit hash and integrated run hash and cannot authorize apply.

### Attack: Automatically retry after a known validation failure

Rejected. The simulation requires `manual_review_required: true` and `retry_allowed_without_manual_review: false`.

### Attack: Downgrade unknown states to normal recovery

Rejected. `unknown_state` must produce `status: failed_closed` and `next_action: manual_review_unknown_state`.
