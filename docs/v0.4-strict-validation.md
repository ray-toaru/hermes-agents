# v0.4 Strict Validation

## Goal

Add strict schema validation and global policy inheritance checks before any future `apply` workflow.

## Non-Goals

- Do not implement automatic apply.
- Do not read real secret values.
- Do not mutate runtime state.
- Do not add business task routing or workflow orchestration.

## Added Controls

- Strict `manifest.schema.json` with `additionalProperties: false`.
- `change-proposal.schema.json`.
- `approval-record.schema.json`.
- `policies/global-permissions.yaml`.
- CLI enforcement that profile manifests cannot remove global forbidden operations.
- CLI enforcement that allowed/approval operations do not overlap forbidden operations.
- CI schema validation through `hermes-agentops validate-schemas`.

## Attack Review

### Design point: make manifest strict

Attack: strict schema may make experimentation slower.
Defense: profile manifests are governance records; unknown fields should be added deliberately through schema evolution, not silently accepted.
Change: none.

Attack: Hermes itself does not require this schema.
Defense: this is AgentOps governance metadata and does not replace Hermes runtime files.
Change: none.

Attack: strict schema may break future fields.
Defense: future fields can be added through explicit schema PRs with review.
Change: none.

Conclusion: locked for v0.4.

### Design point: global forbidden inheritance

Attack: individual profiles may need exceptions.
Defense: global forbidden operations are safety boundaries. Exceptions should require explicit policy change, not local manifest override.
Change: none.

Attack: this is too conservative for high-trust local profiles.
Defense: local trust does not remove audit and secret/runtime safety requirements.
Change: none.

Attack: it duplicates manifest forbidden lists.
Defense: duplication is deliberate defense-in-depth; CLI verifies local manifests preserve global minimums.
Change: none.

Conclusion: locked for v0.4.

## Review

- Official runtime alignment: pass; this does not replace Hermes provider runtime, tool registry, or AIAgent.
- Secret safety: pass; no secret reads are introduced.
- Runtime safety: pass; no runtime mutation is introduced.
- Apply boundary: pass; apply remains unimplemented.
- Long-term evolution: pass; schemas and policies prepare for safer future apply gates.
