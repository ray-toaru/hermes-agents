# v2.9 Production Lock Lifecycle Contract

## Status

v2.9 adds a **design/prototype-only** production lock lifecycle contract. It does not implement real apply and does not release production locks.

`hermes-agentops apply` remains disabled and must continue to return non-zero.

## Added Artifacts

- `docs/PRODUCTION_LOCK_LIFECYCLE_DESIGN.md`
- `docs/examples/production-apply-lock-lifecycle.yaml`
- `schemas/production-apply-lock-lifecycle.schema.json`

- `tests/test_production_apply_lock_lifecycle.py`

## Contract Guarantees

The checker enforces:

- `design_only: true`;
- `mutation_enabled: false`;
- `apply_authorized: false`;
- `lock_release_implemented: false`;
- release is allowed only from `release_eligible`;
- unknown, failed, audit-failed, or recovery states preserve the lock;
- production lock release remains blocked by missing production audit, recovery, and rollback implementation;
- `hermes-agentops apply` still fails closed.

## Attack Review

### Attack: Use the lifecycle contract as permission to implement release

Rejected. `lock_release_implemented` must be false and boundaries require `does_not_release_production_locks: true`.

### Attack: Release after validation success but before audit completion

Rejected. The contract requires production completion audit before release eligibility.

### Attack: Release on unknown state to avoid deadlocks

Rejected. Unknown state preserves the lock and requires manual review before retry or release.

### Attack: Treat this as real mutation readiness

Rejected. This is one prerequisite design/prototype contract. Rollback execution, production audit capture, production recovery, and post-apply validation integration remain blocking implementation slices.

## Result

The next safe implementation slice after v2.9 is still non-mutating: production audit capture contract or rollback execution design/prototype. Real apply remains blocked.
