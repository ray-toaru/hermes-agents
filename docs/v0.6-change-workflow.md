# v0.6 Non-Mutating Change Workflow

## Goal

Add deterministic commands for creating and reviewing change records that can be verified by `changes verify`.

## Non-Goals

- Do not implement automatic apply.
- Do not mutate managed profile files from proposals.
- Do not read real secret values.
- Do not mutate runtime state.
- Do not add business task routing or workflow orchestration.

## Commands

```bash
hermes-agentops changes propose <agent> --title "..." --summary "..." --reason "..."
hermes-agentops changes list [agent]
hermes-agentops changes show <change-id>
hermes-agentops changes diff <change-id>
hermes-agentops changes approve <change-id> --approver <name>
hermes-agentops changes approve <change-id> --approver <name> --decision reject
hermes-agentops changes verify <change-id>
```

## Record Layout

```text
changes/<change-id>/
  proposal.yaml
  diff.patch
  README.md
  approvals/
    <timestamp>_<approver>_<decision>.yaml
```

## Safety Boundary

Approval does not apply changes. `apply` remains intentionally unimplemented.

The commands only write governance records under `changes/`; they do not modify profile files, runtime state, containers, gateway, cron, sessions, logs, or secrets.

## Attack Review

### Design point: add propose/approve before apply

Attack: adding approvals creates pressure to implement apply.
Defense: approval records are only inputs to preflight. They do not grant execution authority.
Change: none.

Attack: writing files under changes/ is still mutation.
Defense: it mutates only governance records, not managed profiles or runtime state. This is acceptable for diff-first audit.
Change: none.

Attack: Git diff as input can miss untracked files.
Defense: v0.6 intentionally captures tracked profile diffs only. Future versions may add untracked-file detection before apply.
Change: none.

Conclusion: locked for v0.6.

## Review

- Secret safety: pass. No secret reads are introduced.
- Runtime safety: pass. No runtime mutation is introduced.
- Hermes runtime alignment: pass. This does not replace provider runtime, tools registry, session storage, gateway, cron, or AIAgent.
- Apply boundary: pass. Apply remains disabled.
- Long-term evolution: pass. Change records now have deterministic creation, review, display, and verification commands.
