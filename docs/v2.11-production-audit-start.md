# v2.11 Production Audit-Start Contract

## Status

v2.11 adds a **design/prototype-only** production audit-start contract. It does not write production audit records, dispatch mutation, or enable real apply.

`hermes-agentops apply` remains disabled and must continue to return non-zero.

## Added Artifacts

- `docs/PRODUCTION_AUDIT_CAPTURE_DESIGN.md`
- `docs/examples/production-audit-start.yaml`
- `schemas/production-audit-start.schema.json`
- `scripts/check-production-audit-start`
- `tests/test_production_audit_start.py`

## Contract Guarantees

The checker enforces:

- `design_only: true`;
- `mutation_enabled: false`;
- `apply_authorized: false`;
- `production_audit_write_implemented: false`;
- `production_audit_written: false`;
- `audit_start_record_created: false`;
- `mutation_command_dispatched: false`;
- `rollback_executed: false`;
- audit-start must be before mutation;
- audit-start failure preserves the lock;
- completion audit is required before release;
- `hermes-agentops apply` still fails closed.

## Attack Review

### Attack: Use audit-start contract as mutation permission

Rejected. Audit-start is accountability evidence only and does not authorize mutation.

### Attack: Treat the example as a production audit record

Rejected. The example requires `production_audit_written: false` and `audit_start_record_created: false`.

### Attack: Allow mutation when audit-start write fails

Rejected. The failure policy requires lock preservation and manual review.

### Attack: Release locks before completion audit

Rejected. The contract requires completion audit before any future release eligibility.

## Result

The next safe implementation slice remains non-mutating: rollback execution contract or production completion-audit contract. Real apply remains blocked.
