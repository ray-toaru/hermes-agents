# v2.2 Test Harness and Internal Dispatch Hardening

## Status

Implemented as a maintainability and verification-safety slice. This does not enable real apply.

## Evidence Observed

The v2.1 subprocess timeout helper made script-level subprocess failures fail closed, but further local verification found two additional facts:

1. Test-level calls still launched many child Python interpreters. In this interactive environment, repeated child interpreters importing `jsonschema` eventually appeared to hang during process startup or cold import. A `subprocess.run(..., timeout=N)` timeout is not sufficient when the parent is blocked before `Popen` returns.
2. `scripts/run-post-apply-validation-sandbox` had a concrete regression from the v2.1 refactor: it called `copy_workspace(...)` after the local helper was removed or not carried forward. The failing test produced:

```text
post-apply validation sandbox runner failed: name 'copy_workspace' is not defined
```

Both findings are direct observations from local test execution, not inferred failures.

## Implemented Changes

- Added `tests/agentops_test_utils.py` for in-process execution of repository scripts exposing `main(argv)`.
- Migrated subprocess-heavy test wrappers for read-only validators, generators, sandbox runners, and prototypes to `run_script(...)`.
- Kept real `git` subprocesses in tests, but wrapped all test subprocess calls with the existing autouse timeout fixture.
- Added `scripts/agentops_common.py::run_python_script_main` and `run_internal_python_command` for reviewed repository-internal Python entry points.
- Updated sandbox-only runners to dispatch internal AgentOps Python commands in-process when the command is an allowlisted repository script.
- Added `scripts/agentops_common.py::copy_workspace_dirs` and used it in the sandbox post-apply validation runner.
- Added regression tests for in-process script execution and cwd restoration.

## Attack / Defense Review

### Round 1

Attack: Replacing subprocess execution in tests could stop testing the real CLI boundary.

Defense: The helper calls the same script `main(argv)` entry points and captures stdout/stderr into a `CompletedProcess` shape. This preserves parser, return-code, validation, and output assertions. A small number of real Git subprocesses remain where Git behavior is the subject under test.

Status: Stable.

### Round 2

Attack: In-process dispatch in sandbox runners could become a hidden execution backdoor.

Defense: It only dispatches existing repository-internal Python scripts when the reviewed allowlist already selected the command. It does not use shell, does not execute record-provided argv for structured commands, and returns the same fail-closed `CompletedProcess` evidence shape.

Status: Stable.

### Round 3

Attack: Loading internal scripts in-process could leak parent process state or current working directory.

Defense: `run_python_script_main` captures stdout/stderr, changes cwd only for the call, restores cwd and `sys.path`, and reloads script-local `agentops_common` when present. Regression tests verify cwd restoration and captured output.

Status: Stable.

### Round 4

Attack: Internal dispatch could validate the wrong files if a sandbox copy differs from source.

Defense: The dispatch resolves the script path relative to the command cwd for relative script paths such as `scripts/hermes-agentops`. Sandbox-only runners pass the sandbox cwd, so validation resolves through the sandbox script tree. Current profile-scoped changes remain the only accepted mutation candidate in the reviewed change workflow.

Status: Stable.

### Round 5

Attack: Fixing `copy_workspace` by adding a common helper might weaken secret/runtime filtering.

Defense: `copy_workspace_dirs` requires explicit forbidden path parts and forbidden filenames from the caller. Existing sandbox boundaries still reject symlinks, `.env`, `secrets.json`, `state.db`, `.git`, logs, sessions, workspaces, workspace, and runtime paths before copying.

Status: Stable.

### Converged Decision

Use in-process dispatch only for reviewed repository-internal Python scripts and test harness execution. Keep external tools such as Git behind argv-only subprocess execution. Treat both subprocess and internal dispatch failures as fail-closed validation failures. Do not use in-process dispatch to authorize apply, acquire/release real locks, execute rollback, read secrets, mutate runtime state, or orchestrate business tasks.

## Remaining Work

- Continue mechanical helper deduplication for validators if needed, but keep it separate from mutation work.
- Add live authenticated approval verification as a separate read-only slice before any integrated sandbox mutation pipeline.
- Keep `hermes-agentops apply` disabled until all mutation prerequisite ADRs are implemented and reviewed.
