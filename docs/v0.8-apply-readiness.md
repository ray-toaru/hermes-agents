# v0.8 Apply-Readiness Gates

## Goal

Add dry-run verification and policy inspection gates before any future mutation path exists.

## Non-Goals

- Do not implement automatic `apply`.
- Do not mutate managed profile files from proposals.
- Do not read real secret values.
- Do not mutate runtime state.
- Do not add business task routing or workflow orchestration.

## Target Commands

```bash
hermes-agentops policy effective [--json]
hermes-agentops policy explain <risk-or-path>
hermes-agentops policy check
hermes-agentops changes verify <change-id> [--check-git-clean] [--check-patch-applicable]
```

## Required Gates Before Any Future Apply

- Policy inspection: show effective forbidden operations, risk thresholds, and critical path patterns without reading secrets.
- Policy validation: fail closed when the policy file is missing, malformed, has unsafe critical path patterns, or weak thresholds.
- Clean Git state: dry-run check for unmanaged profile changes before applying a stored diff.
- Patch applicability: `git apply --check` only; no mutation, no index update, no profile writes.
- Approval chain: retain v0.7 checks for timestamp format, threshold drift, duplicate approvers, rejection records, and diff hash mismatch.

## Design-Only / Still Blocked

- Authenticated approvals remain design-only. Approval records are deterministic governance records, not cryptographic identity proofs.
- File locks remain design-only. No lock file currently grants mutation authority.
- Rollback point creation remains design-only. Rollback is still Git-first and must be explicit before any future apply.
- Post-apply validation remains design-only because `apply` remains disabled.

## Attack Review

### Design point: add dry-run gates without enabling apply

Attack: patch applicability checks may create confidence that apply is safe.
Defense: `git apply --check` only proves the diff can apply to the current worktree; it does not authorize mutation, establish locks, create rollback points, or run post-apply validation.
Result: unchanged.

Attack: Git clean checks can be bypassed by untracked files outside the profile path.
Defense: v0.8 should begin with managed profile path checks to avoid rejecting governance records under `changes/`. A future apply gate should add repository-wide cleanliness with explicit exclusions.
Result: unchanged.

Attack: policy inspection may expose sensitive policy data.
Defense: policy commands should only read repository policy files and hardcoded defaults; they must not read `.env`, secrets, sessions, logs, or runtime state.
Result: unchanged.

Conclusion: locked for v0.8.

## Review

- Secret safety: must remain pass. No secret reads.
- Runtime safety: must remain pass. No runtime mutation.
- Apply boundary: `apply` must remain intentionally unimplemented and non-zero.
- Hermes runtime alignment: this must not replace provider runtime, tools registry, session storage, gateway, cron, or AIAgent.
- Remaining pre-apply work: authenticated approvals, repository-wide clean-state policy, file locks, rollback point creation, patch application sandboxing, post-apply validation, and branch protection verification.
