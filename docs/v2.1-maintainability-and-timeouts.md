# v2.1 Maintainability and Timeout Hardening

## Status

Implemented as a maintainability and fail-closed hardening slice. This does not enable real apply.

## Evidence Observed

During local verification, full test execution exceeded the interactive environment timeout after only a small number of subprocess-heavy tests. Targeted measurement showed Python subprocesses that import `jsonschema` cost several seconds per invocation in this environment:

```text
python -c "import jsonschema"  # observed about 5 seconds locally
```

This is not a correctness failure in one test assertion, but it is an operational hazard: unbounded subprocess calls can make CI or local verification appear hung and can mask the true failing command.

## Implemented Changes

- Added `scripts/agentops_common.py` with shared helpers for:
  - YAML/JSON loading;
  - YAML writing;
  - SHA-256 hashing;
  - UTC timestamp formatting;
  - change ID agent extraction;
  - argv-only subprocess execution with a hard timeout.
- Migrated subprocess call sites in the CLI, pre-apply, lock, rollback prototype, real-lock prototype, structured command sandbox, post-apply sandbox, and apply dry-run scripts to the shared `run_command` helper.
- The shared timeout defaults to 30 seconds and can be overridden with `AGENTOPS_COMMAND_TIMEOUT_SECONDS`.
- Timeout returns exit code `124` and captured stderr evidence instead of hanging indefinitely.

## Attack / Defense Review

### Round 1

Attack: A default timeout could hide a real bug by converting a hang into a generic failure.

Defense: The helper returns a specific timeout exit code and stderr message containing the command and timeout. Existing callers already fail closed on non-zero exits, so this preserves safety while improving evidence.

Status: Stable.

### Round 2

Attack: A timeout could kill legitimate long-running validation such as full `pytest -q`.

Defense: The helper accepts an explicit per-call timeout and an environment override. Real mutation remains disabled, so increasing timeout for validation cannot become execution authority.

Status: Stable.

### Round 3

Attack: Centralizing subprocess execution could accidentally allow shell injection.

Defense: The helper accepts `list[str]` argv only and never uses `shell=True`. Existing command records remain allowlist-driven where execution-adjacent behavior exists.

Status: Stable.

### Round 4

Attack: Central helper imports could break test imports where scripts are loaded by path rather than executed as files.

Defense: `scripts/hermes-agentops` explicitly inserts its script directory into `sys.path` before importing the helper. Direct script execution already has the script directory on `sys.path`.

Status: Stable.

### Converged Decision

Keep subprocess timeout centralized and argv-only. Treat timeout as a fail-closed command failure. Do not use timeout handling to retry, mutate, release locks, or authorize apply.

## Remaining Maintainability Work

This slice centralizes the highest-risk repeated subprocess behavior first. Several validators still contain local YAML/JSON/hash helper functions; migrating those is safe but should be a separate mechanical cleanup to keep review scope narrow.
