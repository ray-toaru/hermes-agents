# v1.7 Approval Identity Evidence

## Status

Implemented as a read-only governance validator. This does not enable `apply`.

## Purpose

Current approval records are review evidence, not cryptographic identity proof. Approval identity evidence records add an explicit contract for binding an approval record to an externally authenticated review source such as a GitHub review, GitHub issue comment, or signed external attestation.

This improves the future apply-readiness chain without pretending that YAML alone proves identity.

## Boundaries

The approval identity validator must not:

- authenticate users by itself;
- treat repository YAML as cryptographic proof;
- apply patches;
- mutate managed profile files;
- mutate runtime state;
- read real secret values;
- acquire or release real locks;
- execute rollback;
- execute business actions;
- route or orchestrate business tasks.

`mutation_enabled` must remain `false`.

## Record Semantics

An approval identity evidence record binds:

- `change_id`;
- `agent` from the change id;
- `approver`;
- `identity_method` and external identity provider;
- `external_identity.subject`;
- `approval_record_sha256`;
- `diff_sha256`;
- explicit assertions that the record does not authorize apply, does not perform live authentication, and does not grant approval authority.

When `--require-approval-file` is used, the validator requires a matching approval record under `changes/<change_id>/approvals/` whose file hash, approver, change id, and diff hash match the identity evidence record.

## Review Notes

- This is identity evidence, not final authentication.
- Future real mutation still needs a separate authenticated approval design.
- GitHub review evidence URLs are references; the validator does not call GitHub or verify live reviewer permissions.
- This layer is useful because it prevents future apply gates from treating bare approval YAML as sufficient.
