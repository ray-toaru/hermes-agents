# v2.7 Real Apply Readiness Review

## Summary

v2.7 adds a structured P5 real-apply readiness review. The review concludes that the project may proceed to a **design-only** real apply PR, but real apply implementation and enablement remain blocked.

Added assets:

- `docs/P5_REAL_APPLY_READINESS_REVIEW_V2.md`
- `docs/examples/p5-real-apply-readiness-review-v2.yaml`
- `schemas/real-apply-readiness-review.schema.json`
- `scripts/check-real-apply-readiness-review`
- `tests/test_real_apply_readiness_review.py`

## Decision

```yaml
ready_to_design_real_apply: true
ready_to_implement_real_apply: false
ready_to_enable_real_apply: false
apply_must_remain_disabled: true
next_allowed_step: real_apply_design_only
```

This means the next PR may write design documents and, if needed, a disabled skeleton that still returns non-zero. It must not mutate profiles, runtime state, secrets, locks, rollback state, audit records, or business workflows.

## Test Runner Finding

During this slice, a monolithic local `pytest -q` invocation again stalled after many sandbox-heavy tests had already passed. The failure mode was not an assertion failure. Split runs covering the same collected tests completed successfully.

Two hardening changes were made:

1. `agentops_common.run_python_script_main()` now has a signal-based timeout for in-process internal script dispatch.
2. `tests/agentops_test_utils.run_script()` now has a signal-based timeout for test in-process script execution.

The CI workflow now runs the suite in explicit groups with plugin autoload disabled and command/script timeouts set. This is a supported validation strategy for the current subprocess-heavy and sandbox-heavy test suite.

The monolithic local stall is still a risk signal, not a permission to skip tests. Real apply implementation should not begin unless grouped CI is green and any future test-runner changes keep fail-closed timeout behavior.

## Boundaries

This slice does not:

- enable `hermes-agentops apply`;
- authorize mutation;
- mutate managed profiles;
- acquire or release production locks;
- execute rollback;
- create production audit records;
- read secret values;
- mutate runtime state;
- orchestrate business tasks.

## Attack Review

### Attack: Treat review evidence as apply authorization

Rejected. The schema and checker require `ready_to_implement_real_apply: false`, `ready_to_enable_real_apply: false`, and `apply_must_remain_disabled: true`.

### Attack: Treat design readiness as feature-flag readiness

Rejected. The only allowed next step is `real_apply_design_only`; no feature flag may enable mutation.

### Attack: Hide unstable tests by splitting the suite

Rejected. The split strategy is explicit, documented, and still covers the full collected suite. It also adds in-process timeouts so future stalls fail closed instead of hanging silently.

### Attack: Let sandbox evidence stand in for production lifecycle controls

Rejected. The readiness review keeps production lock lifecycle, rollback execution, production audit capture, and production recovery as implementation blockers.
